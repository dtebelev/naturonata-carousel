## 1. Что делает эта программа

Streamlit-дашборд, который создаёт Instagram-карусели на русском языке для бренда **Naturonata** (@naturonata). 

**Пайплайн:**
1. Пользователь выбирает аудиторию, формат контента, количество **3–14** слайдов и вставляет текст
2. GPT-4o генерирует сценарий карусели (JSON с заголовками, текстами, акцентами)
3. (Опционально) FLUX-2/Flash генерирует фоновые изображения ИЛИ используется кастомный фон (NEW v5.1)
4. (Опционально) пользователь заменяет первый и/или последний слайд своей готовой картинкой (NEW v5.15)
5. Сценарий собирается в интерактивный HTML-превью (свайп, навигация)
6. Playwright экспортирует каждый слайд в PNG 1080×1350px
7. ZIP-архив для скачивания (клиентский html-to-image + серверный Playwright)

## 6. Технические детали

### 6.1. Формат вывода GPT-4

JSON массив `[{type, headline, body, accent}]`

### 6.2. Промпт GPT-4

См. PROMPT.md, включает аудиторию, формат, CTA → @naturonata, фокус, правила, источник.

### 6.3. HTML-шаблон карусели v5.1

**Размеры:** превью 420×525, экспорт 1080×1350, scale 2.571

**Структура слайда v5.1:**
```
.slide (bg fallback цвет)
  ├── .custom-bg (NEW v5.1, если загружен кастомный фон, opacity из слайдера, z-index 0)
  ├── .bg-image (FLUX фон, opacity 0.2, если нет кастомного фона)
  ├── .custom-ready-slide (NEW v5.15: если загружен готовый первый/последний — только изображение, без overlay)
  │   └── img.custom-ready-slide-image (object-fit:contain)
  └── ИЛИ .slide-content (стандартная карточка)
      ├── .slide-logo (кроме последней карточки, если на ней есть CTA-бейдж)
      ├── .slide-number (только на промежуточных карточках; скрыт на первой и последней)
      ├── .slide-inner
      │   ├── badge (badge_size), deco-line, h2.headline (headline_size), p.body-text (body_size), accent (accent_size)
      │   └── cta-image (последний слайд; абсолютный прозрачный слой)
      └── brand-bar (индивидуальный footer_scale для бренда/@канала)
  ├── progress-bar
  └── swipe-arrow
```

**Критически важно:**
- Логотип и кастомный фон — через CSS class с base64 **один раз**, не в каждом слайде. Это экономит мегабайты.
- `custom_bg_div = '<div class="custom-bg"></div>'` в каждом слайде, а CSS `.custom-bg{background-image:url(...)}` один раз.
- Если `has_custom_bg=True`, то `bg_img_div=""` (FLUX фоны отключаются) и `bg_style = background: {bg}` (fallback).
- На первой и последней карточках `.slide-number` сверху не выводится: номер уже есть в нижнем правом `.progress-counter`, а верхняя позиция нужна для бейджа формата или CTA-дизайна.
- CTA на последнем слайде — отдельный абсолютный слой внутри `.slide-content`: он не растягивает текстовую раскладку и не создаёт свою карточку, рамку или фон. Если CTA-бейдж показан, обычный логотип на этой карточке скрывается.
- `custom_first_slide_b64` и `custom_last_slide_b64` полностью заменяют соответствующий крайний HTML-слайд: на нём нет текста, лого, номера, прогресса, CTA или другого overlay. Картинка показывается без обрезки (`object-fit:contain`), поэтому её лучше подготовить в пропорциях выбранного формата.

### 6.9. Позиция логотипа v5.2 (NEW)

**Задача:** На примере бежевого фона логотип по центру сверху, а программа ставила всегда правый верх.

**Решение:**

1. **Константа LOGO_POSITIONS:**
```python
LOGO_POSITIONS = {
    "Правый верх (дефолт)": {"css": "top:28px; right:32px; left:auto; bottom:auto;", "bg_pos": "center right", "transform": ""},
    "Левый верх": {"css": "top:28px; left:32px;", "bg_pos": "center left"},
    "Центр верх (как на твоём бежевом фоне)": {"css": "top:28px; left:50%;", "bg_pos": "center", "transform": "transform:translateX(-50%);"},
    "Правый низ": {"css": "bottom:80px; right:32px;"},
    "Левый низ": {...},
    "Центр низ": {"css": "bottom:80px; left:50%;", "transform": "translateX(-50%);"},
}
```

2. **Sidebar:** `logo_position_choice = st.selectbox("Позиция логотипа", list(LOGO_POSITIONS.keys()), key="logo_position", help="Центр верх — как на твоём бежевом фоне")`

3. **Session State:** `logo_position` default "Правый верх (дефолт)"

4. **В build функциях:**
```python
pos_info = LOGO_POSITIONS.get(logo_position, LOGO_POSITIONS["Правый верх (дефолт)"])
logo_css = f".slide-logo{position:absolute;{pos_info['css']} {pos_info['transform']} height:38px; ... background-position:{pos_info['bg_pos']}; ...}"
```

5. **Совместимость:** Работает с кастомным фоном — можно выбрать "Центр верх" чтобы логотип был как на примере бежевого фона, или "Правый верх" для классики. Учитывает hide_logo_on_custom_bg.

 Кастомный CTA v5.4 (FIX)

**Проблема:** Пользователь вводит в поле "Кастомный CTA" текст "Напиши в комментарии слово «приз»", а на последнем слайде программа генерирует "Напиши в комментарии слово «приз» и подпишись на @naturonata в телеграмм" — смешивает два действия.

**Причина:** В промпте GPT было всегда:

```
Последний слайд должен вести к: {aud_cta}
Важно: CTA должен вести в Telegram-канал @naturonata
```

Где `aud_cta = custom_cta or audience_default`. GPT видел и кастомный текст, и инструкцию про Telegram, и соединял их.

**Решение v5.4:**

```python
has_custom_cta = bool(custom_cta and custom_cta.strip())
if has_custom_cta:
    cta_block = " ... Используй ТОЧНО этот текст ... НЕ добавляй Telegram ... Одно действие за раз ..."
else:
    cta_block = " ... должен вести в Telegram @naturonata ..."
```

Теперь если кастомный CTA задан — GPT получает жёсткую инструкцию приоритета №1 не добавлять ничего лишнего.

### 6.12. Редактирование слайдов live v5.5 (NEW)

**Задача:** Пользователь хочет менять текст каждой карточки после генерации.

**Решение (безопасно и красиво):**

1. **Session State:**
- `carousel_data` — текущий (редактируемый) массив
- `carousel_data_original` — бекап оригинала GPT-4o для сброса
- `carousel_renderer_version` — версия HTML-рендера, чтобы существующее превью пересобиралось после обновления дизайна
- `edit_headline_i`, `edit_headline_size_i`, `edit_body_i`, `edit_body_size_i`, `edit_badge_size_i`, `edit_accent_i`, `edit_accent_size_i`, `edit_footer_scale_i`, `edit_type_i` — поля ввода для слайда i

2. **При генерации:**
```python
st.session_state.carousel_data = [dict(s) for s in slides_data]
st.session_state.carousel_data_original = [dict(s) for s in slides_data]
for k in list(st.session_state.keys()):
    if k.startswith("edit_"): del st.session_state[k]
```

3. **UI блок 6.5 (между генерацией и превью):**
- `st.markdown("6.5 ✏️ Редактировать")`
- Инициализация ключей если нет
- Кнопки "Сбросить к оригиналу" и "Очистить акценты"
- Цикл `for i in range(len(carousel_data)):` → `st.expander(f"Слайд {i+1} [{type}] — {headline[:40]}")`
  - `selectbox type: hook/content/cta`
  - `text_input accent`
  - `text_input headline` + счётчик >80 симв warning
  - `slider headline_size` 18–48px для размера заголовка конкретной карточки
  - `slider body_size` 12–24px для размера основного текста конкретной карточки
  - `slider accent_size` 11–24px для акцентной строки
  - `slider footer_scale` 70–160% для подписи бренда/@канала внизу
  - `slider badge_size` 8–16px для масштаба всего лейбла на карточке типа `hook`
  - `text_area body` height 140 + счётчик >300 info

4. **Live-обновление без кнопки:**
```python
new_data = []
has_changes = False
for i in range(len(carousel_data)):
    new_slide = {
      "type": session_state[f"edit_type_{i}"],
      "headline": session_state[f"edit_headline_{i}"],
      "headline_size": session_state[f"edit_headline_size_{i}"],
      "body": session_state[f"edit_body_{i}"],
      "body_size": session_state[f"edit_body_size_{i}"],
      "badge_size": session_state[f"edit_badge_size_{i}"],
      "accent": session_state[f"edit_accent_{i}"],
      "accent_size": session_state[f"edit_accent_size_{i}"],
      "footer_scale": session_state[f"edit_footer_scale_{i}"],
    }
    if new_slide != old: has_changes=True
    new_data.append(new_slide)

if has_changes:
    session_state.carousel_data = new_data
    rebuilt_html = build_carousel_html(slides_data=new_data, format_info=..., logo_position=..., logo_size=..., custom_bg_b64=..., ...)
    session_state.carousel_html = rebuilt_html
    # обновить html_path для Playwright
```

5. **Безопасность:**
- Редактируются только текст и размеры текстовых элементов; структура HTML/CSS не меняется
- `type` ограничен списком ["hook","content","cta"] — нельзя ввести произвольное
- Пустой headline/body разрешён, но можно добавить валидацию
- Сброс к оригиналу одной кнопкой
- При новой генерации старые edit_ ключи удаляются — нет конфликтов

6. **Красота и удобство:**
- Expanders: первый открыт, остальные закрыты
- Заголовок expander показывает тип и первые 40 символов заголовка — быстро ориентироваться
- Счётчики символов с warning
- Кнопки управления сверху
- Превью ниже автоматически обновляется — сразу видишь результат
- Работает с кастомным фоном, позицией и размером логотипа, цветами, FLUX

### 6.13. Первый счётчик и увеличенный логотип v5.6 (NEW)

**Задача:** На первой карточке верхний счётчик `1/N` пересекался с бейджем формата («ЛАЙФХАК»). Также предел размера логотипа 80px был недостаточным, а `width:auto` с `min-width:60px` не давал контейнеру логотипа реально расти по ширине.

**Решение:**
- В **обеих** функциях сборки (`build_carousel_html` и `build_zip_export_html`) введён `slide_number_html`: при `i == 0` он пустой, на карточках 2…N выводится прежний `.slide-number`. Нижний правый `.progress-counter` (`1/N`) остаётся на первой карточке и на всех остальных.
- Слайдер `logo_size` теперь имеет диапазон **20–160px** (шаг 2, дефолт 38).
- CSS логотипа в обеих функциях использует контейнер `height:{logo_size}px; width:{logo_size}px` и `background-size:contain`. Поэтому логотип растёт вместе со значением слайдера, его пропорции не искажаются, а base64 по-прежнему добавляется в CSS только один раз.

### 6.14. Прозрачный CTA-слой v5.7 (NEW)

**Проблема:** Дефолтный `cta_image.jpg` был вертикальным JPG с белым фоном. При отображении на карточке он создавал светлый прямоугольник и занимал место в flex-раскладке, из-за чего ломал композицию последнего слайда.

**Решение:**
- Из прозрачного исходника `assets/cta_image.png` подготовлен `assets/cta_badge.png` — обрезанный до 678×681px круг «мама и ребёнок» без прямоугольного фона. Именно он задан как `DEFAULT_CTA_IMAGE_PATH`.
- В `build_carousel_html` и `build_zip_export_html` CTA теперь размещён абсолютным слоем: `.cta-image-container` центрируется по горизонтали и закреплён в нижней части `.slide-content`. Он не участвует в flex-раскладке текста; у изображения нет фона, рамки и тени.
- `.cta-inner` получает нижний отступ, чтобы текст и круглая иллюстрация не пересекались. Изменение одинаково работает в превью, клиентском ZIP и Playwright-экспорте.
- Для собственного CTA в sidebar рекомендован PNG с прозрачным фоном: автоматически удалять фон из произвольных пользовательских файлов программа не пытается.

### 6.15. Гарантия CTA на последней карточке и счётчик v5.8 (FIX)

**Проблемы по скриншоту:** На последней карточке могли одновременно остаться верхний `N/N` и не появиться CTA, если GPT отдал последний элемент с `type="content"` либо в развёртывании ещё не оказался новый файл `cta_badge.png`.

**Решение:**
- В обеих HTML-функциях вычисляется `is_last_slide = i == total - 1`. Верхний `.slide-number` скрывается теперь на **первой и последней** карточках. Нижний правый `.progress-counter` остаётся без изменений.
- Последняя карточка получает CTA-оформление и `cta-image` **независимо от `type`, который вернул GPT**. Поэтому иллюстрация не пропадёт, если последняя карточка ошибочно отмечена как `content`.
- Добавлена `get_default_cta_base64()`: обычно она берёт `assets/cta_badge.png`; если в новом развёртывании этого файла ещё нет, функция создаёт обрезанный прозрачный CTA в памяти из исходного `assets/cta_image.png`. При ошибке остаётся безопасный прозрачный PNG-источник. Таким образом дефолтный CTA не становится пустым из-за несовпадения версии кода и ассетов.
- Правило реализовано и в `build_carousel_html`, и в `build_zip_export_html` — для превью, ZIP и Playwright-экспорта.

### 6.16. Автообновление уже созданного превью v5.9 (NEW)

**Проблема:** Streamlit хранит HTML карусели в `session_state`. После обновления кода пользователь мог видеть старую карточку, пока не сгенерирует карусель заново или не изменит текст вручную — поэтому исправленный CTA или счётчик не появлялись сразу.

**Решение:**
- Введена константа `CAROUSEL_RENDERER_VERSION` и ключ `session_state.carousel_renderer_version`.
- При новой генерации и при live-пересборке сохраняется текущая версия рендера.
- Если пользователь открыл существующую карусель после изменения HTML-шаблона, версия не совпадает: блок live-редактирования пересобирает превью автоматически из текущих `carousel_data` и настроек, даже без правки текста. Это также обновляет HTML для Playwright-экспорта.

### 6.17. Без логотипа на CTA-карточке с бейджем v5.10 (NEW)

**Задача:** Если на последней карточке показан CTA-бейдж с иллюстрацией, логотип бренда в углу дублирует брендинг и перегружает композицию.

**Решение:**
- В обеих HTML-функциях введён `show_cta_badge = is_last_slide and bool(cta_image_b64)`.
- Если `show_cta_badge=True`, `show_logo=False` только для этой последней карточки. На всех остальных карточках логотип остаётся по прежним правилам, включая настройку `hide_logo_on_custom_bg`.
- Если CTA-картинка выключена или недоступна, логотип на последней карточке по-прежнему показывается.
- Правило одинаково работает в превью, ZIP и Playwright-экспорте.

### 6.18. Индивидуальный размер заголовка v5.11 (NEW)

**Задача:** Пользователь должен иметь возможность менять размер букв заголовка на конкретной карточке без изменения типографики остальных слайдов.

**Решение:**
- В каждом expander блока «✏️ Редактировать слайды» добавлен слайдер **«Размер заголовка (px)»** с безопасным диапазоном **18–48px** на превью.
- Значение сохраняется в `headline_size` конкретного слайда и сразу пересобирает превью, клиентский ZIP и Playwright-экспорт.
- Дефолты сохраняют прежний дизайн: `hook` — 32px, CTA — 28px, обычный контент — 24px. Неверные или старые значения нормализуются в допустимый диапазон.
- Размер не затрагивает основной текст, акцент, остальные карточки, цвета, логотип или CTA. При «Сбросить к оригиналу GPT» размер возвращается к дефолту типа слайда.

### 6.19. Индивидуальный размер основного текста и лейбла v5.12 (NEW)

**Задача:** Пользователь должен отдельно менять размер букв основного текста и надписи в лейбле формата («ВИКТОРИНА», «ЛАЙФХАК», «ГАЙД», «ТРЕНДЫ», «МЕНЮ», «ИСТОРИЯ», «ФАКТЫ», «ЧЕК-ЛИСТ») без влияния на другие карточки.

**Решение:**
- В каждом expander добавлен слайдер **«Размер основного текста (px)»** с безопасным диапазоном **12–24px**. Он влияет только на `p.body-text` выбранной карточки.
- На карточке типа `hook`, где отображается лейбл формата, добавлен слайдер **«Размер лейбла целиком (px)»** с диапазоном **8–16px**.
- Значения сохраняются как `body_size` и `badge_size`, нормализуются при сборке HTML и работают в превью, ZIP и Playwright-экспорте.
- Прежние дефолты сохранены: основной текст — hook 17px, CTA 16px, content 15px; лейбл — 10px. «Сбросить к оригиналу GPT» возвращает эти безопасные значения.

### 6.20. Пропорциональный масштаб лейбла v5.13 (FIX)

**Проблема:** Если менять только размер букв в лейбле, зелёный фон, внутренние отступы, скругление и расстояние между буквами остаются прежними. Лейбл выглядит несбалансированно и почти не меняет свой общий размер.

**Решение:**
- Слайдер переименован в **«Размер лейбла целиком (px)»**. Его дефолт — 10px, диапазон — 8–16px.
- Одно значение `badge_size` теперь пропорционально масштабирует **весь лейбл**: размер текста, фон через внутренние отступы, скругление углов и межбуквенное расстояние.
- Масштаб участвует в раскладке страницы (это не CSS `transform`), поэтому лейбл честно занимает больше или меньше места и не налезает на соседние элементы.
- Логика одинаково действует в превью, ZIP и Playwright-экспорте; остальные элементы карточки не меняются.

### 6.21. Размер акцентной строки и подписи @канала v5.14 (NEW)

**Задача:** Пользователь должен менять на выбранной карточке размер акцентной строки (например, «Открой новые подходы в воспитании!») и размер подписи `@naturonata` в нижней части.

**Решение:**
- Добавлен слайдер **«Размер акцентной строки (px)»**: диапазон **11–24px**, дефолт 15px. Он влияет только на `.accent-text` выбранной карточки.
- Добавлен слайдер **«Масштаб подписи внизу (@канал / бренд), %»**: диапазон **70–160%**, шаг 5%, дефолт 100%. Он пропорционально меняет обе нижние подписи: `.brand-name` и `.brand-handle`.
- Масштаб обеих нижних подписей нужен специально для совместимости: `@naturonata` может быть введён либо в поле «Название», либо в поле handle — в обоих случаях размер меняется на конкретной карточке.
- Настройки сохраняются как `accent_size` и `footer_scale`, применяются live в превью, ZIP и Playwright-экспорте. При сбросе возвращаются исходные 15px и 100%.

### 6.22. Готовые первый и последний слайд v5.15 (NEW)

**Задача:** Пользователь должен иметь возможность загрузить сильно проработанную готовую обложку и/или готовый финальный слайд, не ломая обычную генерацию остальных карточек.

**Интерфейс в sidebar:**
- Блок **«Готовые первый и последний слайд»**.
- Независимые чекбоксы **«Использовать готовый первый слайд»** и **«Использовать готовый последний слайд»**.
- У каждого чекбокса свой uploader PNG/JPG/WebP. Можно включить только первый, только последний или оба.

**Поведение:**
- Готовая картинка полностью заменяет первую и/или последнюю карточку как самостоятельный слайд. На ней нет GPT-текста, лейбла, лого, стрелки, номера, нижней подписи, прогресс-бара или CTA-картинки.
- Все промежуточные карточки работают как обычно: сценарий GPT, фоны FLUX, редактор, размеры текста, логотип и CTA.
- Готовые крайние слайды автоматически исключаются из выбора FLUX-фонов, поэтому не тратятся деньги на ненужную генерацию.
- Изображение выводится через `object-fit:contain`: оно никогда не обрезается. Нужно заранее загрузить файл в пропорциях выбранного формата (1:1, 4:5 или 3:4), иначе вокруг изображения появятся поля.
- Функция поддержана одинаково в превью, клиентском ZIP и Playwright-экспорте. Выбери картинки **до** нажатия «Сгенерировать карусель».

### 6.23. До 14 слайдов в карусели v5.16 (NEW)

**Задача:** Пользователь должен создавать длинные карусели до 14 карточек.

**Решение:**
- Слайдер **«Количество слайдов»** расширен с диапазона **3–10** до **3–14**; дефолт остаётся 7.
- Остальная архитектура уже использует `num_slides` динамически: GPT получает точное требуемое число карточек, редактор создаёт нужное количество expander-блоков, выбор FLUX-фонов строит все чекбоксы, навигация и оба экспорта обходят все слайды.
- Сложных изменений не потребовалось. При 11–14 карточках выше время/стоимость генерации и нужно больше исходного материала, поэтому это указано в подсказке слайдера.
